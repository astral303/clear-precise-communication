# Negate the verb, not the object

A negative fact rides the verb or leads the sentence; it never hides
behind a positive verb as a postverb `no <noun>` object. "The search
found no other event" makes the reader file a positive event, then
retract it. The pattern also carries the classic double reading —
"I saw no stars" reads briefly as "I saw no-stars."

## Rewrite

| Do not write | Write |
| --- | --- |
| The search found no other event. | The search didn't find any other event. |
| The output showed no time. | The output did not show the time. |
| `getComponents` returns no rows. | `getComponents` didn't return any rows. |
| The run logged no errors. | The run didn't log any errors. |

Lead form puts the absence first ("No errors were logged."). Use it
when the check's coordinates sit next to the verb without parentheses.

## Scope

Every durable artifact in `always-on-scope.md`, and chat responses.
Product strings are quoted, not rewritten: `No non-editing workflow
process definition found` stays as it is.

## Closed loopholes

- "The shorter form says the same thing." `any` is not padding: negative
  polarity demands it, and its cost is the negation reaching the reader
  before the object is built. `shortest-phrase-that-keeps-the-fact`
  does not overrule this — nothing is lost by writing `didn't find any`;
  the retraction the shorter form forces the reader to perform is the
  cost being spent.
- "The scan row does not name this verb, so *showed no* is allowed."
  The construction is any verb with *no* as its object; the listed
  verbs are examples.
- "No user saw this absence, so `name-it-from-what-the-user-saw.md`
  owns it." A miss in a log, a test, or internal state has no witness.
  The object-absence shape is fixed mechanically — negate the verb
  whoever the reader is.

## Final scan

Search for postverb `no <noun>`: `found no`, `returns no`, `logged
no`, `contains no`, `showed no`. Rewrite per the table above.
