# Shortest phrase that keeps the fact

Write the phrase, write it again shorter, keep the shorter one unless a fact
was lost. Padding is usually proof that the work was done, not the fact the
reader needs.

## Scope

Every durable artifact in `always-on-scope.md`, and chat responses. This is a
rule, not a skill, and it binds the first draft.

## The failure

A clause that names what was checked, instead of delivering what was found:

| Wrote (proves the check) | Write (states the fact) |
| --- | --- |
| in tools summary mode, the mode the viewer opens in | in the default tools summary mode |
| a run of its own under `You`, separate from the agent's | a run of its own, separate from the agent's |
| the exports, the CLI renderer and the clipboard all render it, as verified against each shape | every export shape renders it |

Both columns are accurate. The left one is about the writer.

## No search finds this

Every word is accurate, so no banned-word list and no hook can flag it. It
surfaces only by comparing the phrase with a shorter one that says the same
thing, and that comparison is generation, not detection. Producing the shorter
form *is* the rule; there is nothing else to run.

## Closed loopholes

- "The longer form is more precise." Precision the reader cannot act on is
  padding. If the shorter form drops a fact, keep the fact and cut the rest.
- "It reads correctly." Correct is the bar for a draft, not for sending.
- "The detail shows the claim was verified." Verify it, then state the result.
  The reader did not ask how it was checked.
- "I'll tighten it if they ask." The rewrite happens on the draft being sent.

## Final scan

For each phrase: write the shorter form, and keep it unless a fact was lost.
Delete any clause that names which mode, file, or check was consulted rather
than what it showed. See also `documentation-tone.md` and
`write-from-the-reader.md`.
